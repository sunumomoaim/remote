# junk-risk-checker

ヤフオクの中古カメラ「ジャンク出品」が、本当に未確認のジャンクなのか、
出品者が検品・選別した上でジャンクとして出している「危険なジャンク」なのかを、
**出品者の行動**（現在の出品と過去の落札品）から判定するツールです。

商品 URL を貼る（またはスマホの共有シートから開く）と、数秒で

```
🔴 危険度 82（高）
理由:
 +40 同型番の完動品を 3 件出品・販売した履歴があります
 +20 カメラ専門の出品者です（カメラ関連率 94%）
 +15 部分的な動作確認が書かれています
```

のように返します。AI は使わず、ルールベース（`config/rules.json`）で動きます。

## 考え方

- 商品そのものより **出品者の癖** を見る。同じ型番を「完動品」と「ジャンク」で使い分けている出品者は、
  ジャンクの欠陥を把握している可能性が高い。
- 全品ジャンク・動作未確認で出している出品者（遺品整理など）は、未確認のまま出している可能性が高く、掘り出し物が混ざる。
- 「同型番の完動品あり」だけでは、正直に検品して故障内容を書く業者も危険扱いになる。
  そのため **価格が同型番の完動品に対してどれだけ安いか** を併せて見る。
- 当たりを探すより、爆死を避けることを優先する。精度 70% でも価値がある。

## 必要なもの

- Node.js **22.13 以上**（組み込みの `node:sqlite` を使うため。外部の DB やネイティブモジュールは不要）

## 起動

```bash
cd junk-risk-checker
npm install
npm run dev          # http://localhost:3100
```

本番用:

```bash
npm run build && npm start
```

環境変数:

| 変数 | 既定 | 意味 |
|---|---|---|
| `PORT` | 3100 | 待ち受けポート |
| `DATA_DIR` | `./data` | SQLite ファイルの置き場所 |
| `FETCH_INTERVAL_MS` | 1000 | ヤフオクへの連続アクセスの最小間隔 |
| `MAX_LISTING_PAGES` | 2 | 出品者 1 人あたりの出品一覧ページ数（1 ページ 50 件） |
| `MAX_RATING_PAGES` | 2 | 出品者 1 人あたりの評価ページ数（1 ページ 25 件） |
| `SELLER_CACHE_HOURS` | 24 | 出品者情報のキャッシュ時間 |

## 使い方

### PC

トップページに URL を貼って「判定する」。共有テキストごと貼っても URL だけ抜き出します。

### Android（共有シートから）

1. HTTPS で公開した URL を Chrome で開き、メニューから「ホーム画面に追加」（アプリとしてインストール）
2. ヤフオクアプリで商品の「共有」→「ジャンク危険度」

PWA の Web Share Target を使うので、ネイティブアプリは不要です。
ローカル開発中は `cloudflared tunnel --url http://localhost:3100` や ngrok で HTTPS の URL を作ってください。

### iPhone（ショートカットから）

ショートカットアプリで次のショートカットを 1 つ作ると、共有シートから開けます。

1. 新規ショートカット → 詳細で「共有シートに表示」をオン、受け取る種類は「URL」と「テキスト」
2. アクション「URL」: `https://<あなたのサーバー>/share?text=` の直後に変数「ショートカットの入力」を置く
3. アクション「URL を開く」

### API

```
GET /check?url=<商品URL>                 判定して結果ページへ
GET /check?url=<商品URL>&format=json     JSON で返す
GET /check?url=<商品URL>&format=json&debug=1   各ルールの判定結果も返す
GET /share?text=<共有テキスト>            共有シートの受け口（URL を抜き出して /check へ）
GET /checks/:id                           保存済みの結果ページ
POST /checks/:id/outcome                  action=bought|skipped, outcome=working|minor|major
GET /history                              判定履歴
```

## データの取り方

出品者 1 人あたり最大 5 ページ、1 秒以上の間隔でアクセスし、24 時間キャッシュします。

| ページ | 取るもの | 形式 |
|---|---|---|
| 商品ページ | タイトル、説明文、出品者 ID、価格、カテゴリ、画像 | `__NEXT_DATA__` の JSON |
| 出品者の出品一覧 (`/seller/<id>?b=1&n=50`) | 出品中のタイトル・価格・即決価格 | `__NEXT_DATA__` の JSON |
| 出品者の評価一覧 (`/jp/show/rating?auc_user_id=<id>&role=seller&apg=N`) | 過去に落札された商品のタイトル | HTML（旧式テーブル） |

評価ページを使うことで、過去の落札品が初回アクセスから取れます（日次クロールで貯める必要がない）。
ただし評価ページの落札品には価格が無いので、価格比較は出品中の同型番完動品だけを使います。

ページ構造が変わったら `test/fixtures/` の HTML を取り直してテストで検知してください。
セレクタや JSON のパスは `src/yahoo/` にまとまっています。

## ルールの調整

`config/rules.json` を編集するだけで、コードを変えずにルールを追加・調整できます。

```json
{
  "id": "same_model_working_exists",
  "when": { "metric": "same_model_working_count", "op": ">=", "value": 1 },
  "score": 40,
  "reason": "同型番の完動品を {same_model_working_count} 件出品・販売した履歴があります"
}
```

- `when` は `{metric, op, value}`、`{text: "description"|"title", includes_any: [...]}`、`{all: [...]}`、`{any: [...]}`、`{not: {...}}` を組み合わせる
- 指標が算出できない（null）条件は当たらない
- `reason` の `{metric}` は値に、`{metric_pct}` は百分率に置き換わる
- `base` から始めて当たったルールの `score` を足し、0〜100 に収める

使える指標は `src/types.ts` の `Metrics` を参照。語彙は `config/vocab.json`、型番辞書は `config/models.json`。

結果画面の「買った / 見送った」「完動 / 軽症 / 重故障」を記録しておくと、
あとで重みを調整する材料になります。100 件程度たまるまでは重みを頻繁に変えないのがおすすめです。

## 注意

- ヤフオク・メルカリとも自動取得を利用規約で制限しています。このツールは個人利用の前提で、取得ページ数と間隔を絞っています。他人に公開・販売する場合は別途検討してください。
- メルカリ、画像分析、利益予測、通知、学習型スコアリングは未対応です。
