# ジャンク危険度チェッカー — Antigravity 向け指示文

ヤフオクの中古カメラ「ジャンク出品」について、出品者の現出品・過去出品から
「選別済みの危険なジャンクか」を判定するアプリを、Antigravity に作らせるための指示文です。

使い方:

1. **「指示文 1」をそのまま貼る**（アプリ全体の仕様。これだけで Antigravity に全体像を渡す）
2. 続けて **「指示文 2」を貼る**（最初に作らせる範囲を絞る。これを貼らないと全部一気に作ろうとする）
3. 動いたら **「指示文 3 → 4 → 5」** を順に貼る

ChatGPT 案からの主な変更点:

- データの入手経路を 3 ページ（商品ページ / 出品者の出品一覧 / 評価ページ）に明示した。
  特に **評価ページ**を使うと、過去に落札された商品のタイトルが初回アクセスから取れるので、
  「毎日クロールして貯める」前提が不要になる。
- 「同型番の完動品あり → 危険」だけでは、正直に検品して売っている業者も危険扱いになるので、
  **価格が相場に対して安すぎるか**を必ず併せて見るようにした。
- 共有の受け口は **ネイティブアプリではなく Web アプリ**にした。
  Android は PWA の Web Share Target、iPhone はショートカットアプリで URL を渡す。
  ストア審査もアプリ開発も不要。
- 取得ページ数とアクセス間隔に上限を設け、利用規約・Bot 対策のリスクを下げた。
- 「買った / 買わなかった / 結果どうだったか」を最初から記録し、将来の学習データにする。

## 指示文 1: アプリ全体の仕様（最初に貼る）

```md
# アプリ概要

中古カメラの「ジャンク出品」が、
本当に未確認のジャンクなのか、
それとも出品者が検品・選別した上でジャンクとして出している「危険なジャンク」なのかを
判定する Web アプリを作りたい。

対象はまずヤフオクのみ。メルカリは対応しない。

ユーザーはスマホのヤフオクアプリ（またはブラウザ）から商品 URL を「共有」し、
この Web アプリで開く。アプリは URL を解析して「危険度」とその理由を数秒で表示する。

判定の中心は商品そのものではなく「出品者の行動」である。
- 同じ型番を完動品とジャンクで使い分けている出品者は、ジャンクの欠陥を把握している可能性が高い
- 全品ジャンク・動作未確認で出している出品者（遺品整理など）は、掘り出し物の可能性が高い

# MVP の目的

AI は使わず、ルールベースで実装する。
目的は「このジャンクは避けた方がいいか」を数秒で判断できるようにすること。
当たりを探すことより、爆死（高額ジャンクが重故障）を避けることを優先する。

# 技術スタック（必ずこれに従う。勝手に変えない）

- 言語: TypeScript (Node.js 20 以上)
- サーバー: Hono
- HTML 解析: cheerio（まずは fetch + cheerio。JavaScript 実行が必要になった場合のみ Playwright を検討する）
- DB: SQLite（better-sqlite3）。ファイル 1 つで動くこと
- フロント: 素の HTML + 少量の JavaScript。フレームワーク不要。PWA として manifest.json を持つ
- テスト: vitest。HTML 解析は保存した HTML フィクスチャに対してテストする
- パッケージマネージャ: npm

# 必須機能

## 1. URL の受け取り

次の 3 経路すべてで同じ解析 API を呼ぶ。

- 画面上のテキスト欄に URL を貼り付けて「判定」ボタン
- `GET /check?url=...` で直接開く（iPhone のショートカットアプリから呼ぶ想定）
- PWA の Web Share Target（manifest.json の `share_target`）。Android の共有シートから URL を受け取る

受け取った URL は次を許容する:
- `https://page.auctions.yahoo.co.jp/jp/auction/<auctionId>`
- `https://auctions.yahoo.co.jp/...` 配下の短縮・モバイル形式
- 共有テキストの中に URL 以外の文字が混ざっていても URL だけを抽出する

## 2. 商品ページ解析

商品ページから次を取得する:

- 商品タイトル
- 商品説明（本文）
- 出品者 ID
- 現在価格（即決価格があればそれも）
- 商品画像 URL（保存するだけ。MVP では解析しない）
- カテゴリ
- 終了日時

タイトルから「メーカー + 型番」を正規化して抽出する（例: `Canon AE-1`, `Nikon F3`, `Leica M3`）。
型番抽出は正規表現ベースでよいが、辞書ファイル（JSON）で追加・修正できるようにする。

## 3. 出品者分析

出品者 ID をもとに次の 2 ページを取得する。

a. 出品者の出品一覧ページ（現在出品中の商品タイトル・価格）
b. 出品者の評価ページ（過去に落札された商品のタイトル。これが「過去出品」の代わりになる）

取得ページ数は出品者 1 人あたり合計 5 ページまで。
ページ取得の間隔は 1 秒以上あける。
取得結果は SQLite にキャッシュし、同じ出品者は 24 時間以内なら再取得しない。

各タイトルを次の 3 つに分類する:
- 完動品系（「完動」「動作確認済」「美品」「良品」など）
- ジャンク系（「ジャンク」「現状」「動作未確認」「不動」など）
- 不明

分類に使う語彙は JSON ファイルで管理する。

出品者ごとに次の指標を計算する:

- 総件数（出品中 + 評価から取れた過去分）
- ジャンク率
- 完動品率
- カメラ関連率（タイトルにカメラ・レンズ関連語を含む割合）
- 同型番の完動品あり（今回の商品と同じ型番を完動品系で出品・落札した履歴があるか）
- 修理知識語彙率（説明文・タイトルに「モルト交換」「シャッター幕」「清掃済」「OH」「分解」などを含む割合）

## 4. 価格の相場比較

今回の商品の価格を、同じ型番の落札相場と比べる。
相場データは MVP では「同型番の完動品系の価格（出品者一覧・評価ページから取れたもの）」の中央値を使う。
外部の相場サービスは使わない。

出す値: 価格比率 = 今回の価格 ÷ 同型番完動品の中央値（データがなければ null）

## 5. 危険判定（ルールベース）

危険度を 0〜100 で出す。
ルールと重みはコードにハードコードせず、`rules.json` に置いて後から調整できるようにする。

初期ルール（`rules.json` の初期値）:

| 条件 | 危険度への加算 |
|---|---|
| 同型番の完動品の出品・落札履歴がある | +40 |
| 出品者のカメラ関連率が 70% 以上 | +20 |
| 修理知識語彙率が高い | +15 |
| 説明文に「詳しくない」「素人」「わかりません」がある | +10 |
| 説明文に部分確認（「シャッター切れました」「露出計動きます」「ファインダー綺麗」など）がある | +15 |
| 出品者のジャンク率が 90% 以上（全品ジャンク系） | -30 |
| 説明文に「遺品」「実家」「倉庫整理」「まとめて」がある | -15 |
| 価格比率が 0.15 未満（相場に対して非常に安い） | -20 |
| 価格比率が 0.4 以上（ジャンクなのに高い） | +15 |

注意: 「同型番の完動品あり」は、正直に検品して故障内容を書いている業者でも成立する。
そのため価格比率が低い（欠陥を価格に織り込んでいる）場合は危険度を下げる方向に働くようにし、
この相互作用がルールの組み合わせで表現できることを確認する。

結果として返すもの:
- 危険度（0〜100）
- ランク（低: 0〜30 / 中: 31〜60 / 高: 61〜100）
- 当たったルールの一覧（人が読める理由文つき）
- 出品者の指標一覧
- 価格比率

## 6. 結果の記録

判定結果はすべて SQLite に保存する（URL、商品情報、出品者指標、危険度、当たったルール、日時）。

結果画面に次のボタンを置き、ユーザーの行動と結果を記録する:
- 「買った」「見送った」
- 買った場合はあとから「完動だった」「軽症（モルト・清掃程度）」「重故障」を 1 タップで記録

これは将来の学習データになるので、最初から必ず入れる。

## 7. UI

シンプルでよい。スマホの画面幅で読めること。

表示項目:
- 危険度と ランク（色分け: 低=緑 / 中=黄 / 高=赤）
- 理由（当たったルールを日本語で箇条書き）
- 出品者の傾向（件数、ジャンク率、完動品率、カメラ関連率、同型番完動あり）
- 価格比率
- 「買った」「見送った」ボタン
- 過去の判定履歴一覧（別ページ）

表示例:

  🔴 危険度 82（高）

  理由:
  ・同型番（Canon AE-1）の完動品を過去に 3 件販売
  ・カメラ専門出品者（カメラ関連率 94%）
  ・「モルト交換」「シャッター幕」などの修理知識語彙あり
  ・説明文に「詳しくないため」

  出品者: 出品中 38 件 / 過去 120 件、ジャンク率 31%、完動品率 55%

# 技術方針

- 速度優先。1 回の判定は 5 秒以内を目標にする
- AI・LLM は使わない
- ヤフオクへのアクセスは出品者 1 人あたり最大 5 ページ、間隔 1 秒以上、User-Agent は通常のブラウザ相当
- 取得できなかった場合はエラーで落とさず「出品者情報を取得できませんでした」と表示し、商品説明だけで判定した結果を返す
- ヤフオクの HTML 構造は変わる可能性があるので、セレクタは 1 ファイルにまとめ、フィクスチャテストで検知できるようにする
- 個人利用を前提とする。他人に公開する前提の機能（認証、課金）は作らない

# 優先順位

1. URL 受け取り（テキスト欄 + `/check?url=`）
2. 商品ページ解析
3. 出品者 ID 抽出
4. 出品者の出品一覧・評価ページ取得とキャッシュ
5. 型番抽出と同型番比較
6. ルール判定（rules.json）
7. UI 表示と結果記録
8. PWA（manifest.json、Web Share Target）

# 将来的に追加したい機能（今は作らない）

- メルカリ対応
- 画像分析
- Chrome 拡張（PC 用、ページ上に直接表示）
- 利益予測（完動化確率 × 完動相場 − 仕入れ − 修理工数）
- 保存検索と通知
- 記録した結果からの学習型スコアリング
```

## 指示文 2: 最初に作る範囲を絞る（指示文 1 の直後に貼る）

```md
最初から全部は作らないでください。

まず次だけを実装してください:

1. `npm run dev` でサーバーが起動する
2. `GET /check?url=<ヤフオク商品URL>` を叩くと、商品ページを取得して
   タイトル・説明・出品者 ID・価格・型番を JSON で返す
3. 商品ページの HTML を `fixtures/` に 1 つ保存し、解析のテストを vitest で書く

出品者分析・ルール判定・UI はまだ作らないでください。
ヤフオクの実際の HTML を取得してセレクタを確認してから進めてください。
取得に失敗する場合は、失敗した URL と HTTP ステータス、レスポンスの先頭 500 文字を報告してください。
```

## 指示文 3: 出品者分析（指示文 2 が動いたら貼る）

```md
次に出品者分析を実装してください。

1. 出品者の出品一覧ページと評価ページを取得し、商品タイトルと価格の一覧を返す関数を作る

取得は出品者 1 人あたり合計 5 ページまで、間隔は 1 秒以上あけてください。
`GET /check?url=` のレスポンスに出品者指標を追加してください。
```

## 指示文 4: ルール判定と UI（指示文 3 が動いたら貼る）

```md
次にルール判定と結果画面を実装してください。

1. `config/rules.json` に仕様の初期ルールを入れ、JSON を読んで危険度を計算する
2. ルールは「条件（指標名・比較演算子・しきい値、または説明文に含む語句）」と
   「加算値」と「理由文」の 3 つで表現し、コードを変えずに追加・調整できるようにする
3. 「同型番の完動品あり」かつ「価格比率が低い」の組み合わせで危険度が下がることを
   テストで確認する
4. 結果画面（スマホ幅）を作る。仕様の表示例に沿うこと
5. 「買った」「見送った」ボタンと、買った場合の結果記録（完動 / 軽症 / 重故障）を実装し、
   SQLite に保存する
6. 判定履歴の一覧ページを作る

ルールのしきい値を変えたときに結果がどう変わるか確認できるよう、
`GET /check?url=...&debug=1` で各ルールの判定結果と指標の生値を返してください。
```

## 指示文 5: 共有の受け口（指示文 4 が動いたら貼る）

```md
最後に、スマホの共有シートから開けるようにしてください。

1. `manifest.json` を追加し、PWA としてホーム画面に追加できるようにする
2. `share_target` を設定し、Android の共有シートから URL（またはテキスト）を受け取ったら

iPhone はショートカットアプリから `/check?url=` を開く形で使うので、
アプリ側の追加実装は不要です。URL パラメータで受け取れることだけ確認してください。
```

## iPhone から共有で開く手順（ショートカットアプリ、実装不要）

1. ショートカットアプリで新規ショートカットを作る
2. 「共有シートに表示」をオンにし、受け取る種類を「URL」と「テキスト」にする
3. アクション「URL を取得」で入力から URL を取り出す
4. アクション「テキスト」で `https://<自分のサーバー>/check?url=` の後ろに取り出した URL をつなぐ
5. アクション「URL を開く」でそのテキストを開く
6. ヤフオクアプリの共有シートからこのショートカットを選ぶと、結果画面が開く

Android はホーム画面に追加した PWA が共有シートに出るので、そのまま選べばよい。

## 運用上の注意

- ヤフオク・メルカリとも自動取得を利用規約で制限している。この MVP は個人利用の前提で、
  取得ページ数と間隔を絞っている。他人に公開・販売する場合は別途検討すること。
- 評価ページから取れる過去落札は件数に上限がある。それ以上の履歴が必要になったら、
  判定した出品者を定期的に再取得して SQLite に貯めていく方式に切り替える。
- 精度は「買った / 結果」の記録が 100〜300 件たまってから `rules.json` の重みを調整する。
  それまでは重みを頻繁に変えない。
